# 冲压机冲次声音核对

值班员上传**正常循环参考录音**与**待检循环录音**，系统从音频中提取冲击并按参考节奏匹配，自动标出**漏冲对应的参考冲次**与**多冲的实录时刻**，网页可定位播放标出的时段。

另外提供**送料啸声追踪**入口：上传一段录音（格式同下），填写啸声清楚处的时刻、近似频率和每秒最大频率变化量，系统从该时刻起在 200～2000 Hz 内追踪窄带谱峰，网页按原录音时间画出频率轨迹，点击任一区段可定位播放。

## 输入约定

- WAV（PCM）：16 kHz、16-bit、单声道，单个文件不超过 8 秒
- 参考录音：含 4～8 次清晰冲击，相邻冲击间隔至少 150 ms
- 待检录音：允许起始静音、整体响度变化、漏冲、多冲；正常冲次间隔相对参考允许 ±15% 变化

## 判定规则

1. **冲击检测**：短时能量包络 + 自适应门限（门限跟随录音自身峰值，对整体响度变化不敏感）+ 局部极大值拾取。
2. **回声处理**：同一冲击 40 ms 不应期内的峰（含衰减拖尾、回声）只保留最强一个，回声不计多冲。
3. **节奏匹配（动态规划）**：以参考冲次序号为基准做最优对齐，成本 = 漏冲数 + 多冲数；相邻匹配的累计时长须落在参考节奏 ±15% 窗口内。
4. **漏冲不错位**：漏冲只计一次成本，后续冲次仍按参考序号继续对齐，不会整体错位。
5. **歧义人工复听**：若多种归属具有相同的最优成本（同样满足节奏与最少漏/多冲），返回 `ambiguous`，网页给出醒目提示，不武断放行。
6. **无效音频不覆盖结果**：格式/时长/参考质量不合格时返回 400 且不写入状态，上一次有效结果原样保留。

## 送料啸声追踪规则

1. **起点**：在指定时刻 ±50 ms、近似频率 ±60 Hz 内找窄带谱峰；峰需持续至少两帧、且不处在多条谱线贴近处，否则返回 400 并说明原因。
2. **谱峰检测**：64 ms 汉宁窗、10 ms 帧移、2048 点 FFT，取 200～2000 Hz；保留高于本帧底噪、比局部平滑谱突出、且在本帧动态范围内的局部极大值，并剔除只出现一帧的瞬时峰。
3. **走向约束**：下一帧的峰与当前频率之差不得超过「每秒最大频率变化量 × 帧间隔 + 12 Hz 测量容差」。
4. **谱峰交叉**：多个峰都符合变频上限时，按近期斜率外推选最接近的一个继续；交叉处及其后可成立的区段标为**待复听**（不会武断选一条）。
5. **短中断**：连续无可用谱峰超过 120 ms 即停止；≤ 120 ms 时只有缺口另一端的峰唯一且符合变频上限才续接，缺口本身标为**缺测**。中断处有多个可选峰时停止追踪并提示人工复听。
6. **无效输入不覆盖轨迹**：参数非法、音频不合格、起点找不到清晰谱峰时返回 400，上一次轨迹保留。

判定时会扣除分析窗造成的约 32 ms 检测展宽，使 120 ms 规则对应实际中断时长。

## 启动（Docker Compose）

```bash
docker compose up --build
# 浏览器打开 http://localhost:8000
```

录音与结果数据保存在命名卷 `press-data`（容器内 `/data`）。

## 本地开发（无 Docker 时）

```bash
python3 -m pip install -r requirements.txt
uvicorn app.main:app --host 0.0.0.0 --port 8000
# 自定义数据目录：APP_DATA_DIR=/some/dir uvicorn app.main:app
```

## API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `POST` | `/api/inspect` | multipart 表单字段 `reference`、`test`（均为 .wav），返回核对结果 |
| `GET` | `/api/result/last` | 最近一次有效结果（无结果时 404） |
| `DELETE` | `/api/result/last` | 清除内存中的最近结果 |
| `POST` | `/api/track/whistle` | multipart：`audio`（.wav）+ `start_time`、`start_freq`、`max_rate_hz_s`（表单文本），返回频率轨迹 |
| `GET` | `/api/track/last` | 最近一次有效啸声轨迹（无结果时 404） |
| `DELETE` | `/api/track/last` | 清除内存中的最近轨迹 |
| `GET` | `/api/health` | 健康检查 |
| `GET` | `/data/uploads/{name}` | 回传已上传录音，供网页播放器定位播放 |

结果关键字段：`verdict`（`ok` / `defect` / `ambiguous`）、`missed[].ref_index`（漏冲对应的参考冲次，从 0 开始）、`missed[].expected_time`（待检中预计应出现的时刻）、`extras[].time`（多充实录时刻）、`matches`（匹配明细）、`warnings`（回声抑制、歧义等提示）。

啸声追踪结果关键字段：`params`（实际采用的起点与变频上限）、`segments[]`（`kind` = `track` / `ambiguous` / `gap`，含起止时刻、起止频率与轨迹点 `[time, freq]`）、`track.stop_time` / `stop_reason` / `stop_text`（停止位置与原因）、`audio.url`（回传录音）、`summary`（待复听/缺测总时长）、`warnings`。

## 目录结构

```
app/
  audio.py       WAV 校验与冲击检测
  matching.py    节奏匹配动态规划（漏冲/多冲/歧义）
  tracking.py    送料啸声窄带谱峰追踪（交叉/短中断/停止规则）
  service.py     检查服务与结果存储（无效输入不覆盖旧结果）
  main.py        FastAPI 路由（核对 + 啸声追踪）
  static/        单页前端（两个页签：冲次核对、啸声追踪）
tests/           检测、匹配、追踪、端到端 API 测试（57 项）
scripts/         演示 WAV 生成
```
